# Day 34 · nohup 与 2>&1

2026-10-25 · macOS 26.5 · zsh

> **今天只解决一个问题：让程序在后台一直跑，而且出问题能查。**
>
> 其他内容（ssh / rsync / systemd / tar）**等有服务器再学** —— 现在学了没地方用。

---

## 一、核心：两件事

| 需求 | 用什么 |
|---|---|
| **程序放后台，关终端也不死** | `nohup ... &` |
| **输出（含报错）全存进文件** | `> app.log 2>&1` |

**合起来就是这一行** ⭐：

```bash
nohup 你的命令 > 日志文件 2>&1 &
```

例：

```bash
nohup python -m uvicorn app:app --port 8000 > app.log 2>&1 &
```

**停掉它**：

```bash
kill $(lsof -ti :8000)
```

## 二、拆开这一行

```bash
nohup  python3 app.py  > app.log 2>&1  &
└─┬─┘  └─────┬─────┘  └──────┬──────┘  │
  │          │               │         └── ③ 放到后台
  │          │               └──────────── ② 输出都存进 app.log
  │          └──────────────────────────── ① 你要跑的命令
  └─────────────────────────────────────── ④ 断开终端也不死
```

| 部分 | 作用 | 不加会怎样 |
|---|---|---|
| **`&`** | 放后台 | 终端被占住，你啥也干不了 |
| **`nohup`** | 断开终端不死 | 关掉终端，程序就死了 |
| **`> app.log 2>&1`** | 输出存文件 | 关掉终端后，输出全丢了 |

## 三、⭐ `2>&1` 是什么

### 程序有两条输出管道

```
你的程序
 ├── 管道 1（stdout，编号 1）→ 正常消息："服务启动了"
 └── 管道 2（stderr，编号 2）→ 报错：Traceback / ValueError
```

| 编号 | 名字 | 装什么 |
|---|---|---|
| `0` | stdin | 输入 |
| `1` | **stdout** | **正常消息** |
| `2` | **stderr** | **报错** |

### `>` 只接了管道 1

```bash
python3 app.py > a.log
```

| 位置 | 内容 |
|---|---|
| 终端 | **Traceback** |
| `a.log` | **只有正常消息** |

> **⚠️ 这是第一大坑**：**你以为日志存好了，其实报错全丢了。**

### `2>&1` 把管道 2 也接过来

```bash
python3 app.py > app.log 2>&1
```

```
2>&1
│ │ │
│ │ └── 管道 1（正常消息）
│ └──── "指到"
└────── 管道 2（报错）
```

**翻译**：**"把管道 2 也指到管道 1 现在指的地方去。"**

**管道 1 指 `app.log`，所以管道 2 也进 `app.log`。**

### ⚠️ 顺序不能反

```bash
命令 > app.log 2>&1     # ✅ 正确
命令 2>&1 > app.log     # ❌ 错（2 指向了旧终端，再改 1 已经晚了）
```

**记法**：**`> 文件 2>&1` 永远是这个顺序。**

## 四、`nohup` 的三个缺点

| 缺点 | 后果 | 解法 |
|---|---|---|
| 不会开机自启 | 重启服务器就没了 | `systemd` |
| 崩溃不会重启 | 挂了就一直是挂的 | `systemd` |
| 日志不会轮转 | `app.log` 涨到几十 GB 撑满磁盘 | `logrotate` / journal |

> **所以 `nohup` 只适合"临时跑一下"。生产用 `systemd`（以后学）。**

## 五、踩的坑

| # | 现象 | 原因 | 正确做法 |
|---|---|---|---|
| 1 | 日志文件是空的 / 只有一半 | **忘了 `2>&1`** | `> app.log 2>&1` |
| 2 | `2>&1 > app.log` 不生效 | **顺序反了** | `> app.log 2>&1` |
| 3 | `[1] + exit 1` 以为 nohup 失败了 | **exit 1 是程序自己的退出码** | 看日志才知道为什么 |
| 4 | `[1] + exit 127` | **命令拼写错**（`command not found`） | `which 命令` 验证 |
| 5 | 关掉终端服务就没了 | 只用了 `&`，没加 `nohup` | 加 `nohup` |
| 6 | 终端被占住，打不了字 | 忘了 `&` | `Ctrl+C` 退出，加 `&` 重来 |

## 六、建文件的几种方式（今天顺手学的）

```bash
touch a.txt                        # 空文件
echo '一行内容' > a.txt            # 一行
cat > app.py <<'END'               # ⭐ 多行最方便
第一行
第二行
END
printf '第一行\n第二行\n' > c.py   # 用 \n 换行
```

**编辑器**：

```bash
nano app.py     # 新手推荐：Ctrl+O 保存，Ctrl+X 退出
vim app.py      # 功能强但难（Esc 然后 :wq）
code app.py     # VS Code
```

**`<<'END'` 的引号不能少** —— 加了引号，里面的 `$变量` 才不会被替换。
