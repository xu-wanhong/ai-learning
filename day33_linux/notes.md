## 一、端口是什么（先把概念说清）

### 1. IP + 端口

**你电脑上同时跑着很多程序**（浏览器、微信、你的服务……）。
**问题**：网络上来了一包数据，操作系统怎么知道给谁？

| 东西 | 定位什么 | 例子 |
|---|---|---|
| **IP 地址** | **哪一台电脑** | `127.0.0.1`、`192.168.1.5` |
| **端口号** | **那台电脑上的哪个程序** | `8000`、`443`、`22` |

**类比**：**IP = 哪栋楼；端口 = 楼里的门牌号。**

**端口范围**：

```
0 ~ 65535
0 ~ 1023        ← 系统保留（80 网页 / 443 HTTPS / 22 SSH），用要 sudo
1024 ~ 65535    ← 你随便用（8000 就在这）
```

### 2. "接"是怎么回事

| 谁 | 做什么 | 叫法 |
|---|---|---|
| **服务端**（你的 FastAPI） | **先开门，在门口等** | **`listen`（监听）** |
| **客户端**（浏览器 / curl） | **主动去按门铃** | **`connect`（连接）** |
| 两边握上手 | 建立了连接 | **`ESTABLISHED`** |

**实测（服务端 8000 + 客户端连上去，然后 `lsof -i :8000`）**：

```
COMMAND   PID USER ... NAME
Python  42168  hzj ... TCP 127.0.0.1:8000 (LISTEN)                        ← 服务端：开门等
Python  42168  hzj ... TCP 127.0.0.1:60882->127.0.0.1:8000 (ESTABLISHED)  ← 客户端：60882 接到 8000
Python  42168  hzj ... TCP 127.0.0.1:8000->127.0.0.1:60882 (ESTABLISHED)  ← 服务端：接住了
```

**一个连接 = 四条信息**：

```
（客户端 IP : 客户端端口）  ↔  （服务端 IP : 服务端端口）
     127.0.0.1 : 60882            127.0.0.1 : 8000
```

> **客户端也占一个端口** —— 系统随机给的"临时端口"（49152~65535），用完释放。

### 3. 端口的三条铁律

**铁律 1：一个端口，同一时间只能被一个程序监听**

**这就是 `Address already in use` 的全部原因。**

**铁律 2：`127.0.0.1` 和 `0.0.0.0` 不是一回事** ⭐

| 绑哪个 | 谁能访问 | `lsof` 里显示 |
|---|---|---|
| **`127.0.0.1`** | **只有本机** | `127.0.0.1:8000 (LISTEN)` |
| **`0.0.0.0`** | **所有网卡** | `*:8000 (LISTEN)` |

**服务"本地好好的、上服务器就访问不了" → 90% 是绑了 `127.0.0.1`。**

**铁律 3："连不上"只有三种可能**

| 现象 | 原因 | 查什么 |
|---|---|---|
| **连接被拒绝** | 门上没人 | `lsof -i :端口` |
| **连接超时** | 门在，路不通（防火墙/绑错地址） | 看绑的是不是 `0.0.0.0` |
| **404 / 500** | 门通了，业务逻辑问题 | **不是端口问题** |

## 二、⭐ 排障三连（背下来）

```
① 进程在不在？    pgrep -fl 进程名
② 端口在不在？    lsof -i :端口 -P -n
③ 日志说什么？    tail -100 app.log | grep -i error
```

**外加第 0 步**（前三条都正常但访问不了）：

```
④ 绑的是 127.0.0.1 还是 0.0.0.0 ？
```

**判断顺序很重要**：

```
② 没输出 → 回头查 ①
① 也没输出 → 服务根本没启动，不用往下查了
```

## 三、命令速查

### 看进程

```bash
pgrep -fl 进程名                  # ⭐ 最方便（PID + 完整命令）
ps aux | grep -v grep | grep x   # 老写法
ps -o pid,%cpu,%mem,command -p PID   # 只看某个 PID
top                              # 实时看谁在吃 CPU/内存
```

**⚠️ `ps aux | grep x` 会把自己的 grep 也匹配进去** —— 要 `grep -v grep`。

### 看端口

```bash
lsof -i :8000            # 谁占着 8000
lsof -i :8000 -P -n      # ⭐ 数字端口 + 不解析主机名（快）
lsof -ti :8000           # ⭐ 只输出 PID（方便 kill）
lsof -i -P -n | grep LISTEN    # 所有在监听的门
lsof -p 12345            # 某个进程打开的所有东西
```

**⚠️ 大小写不一样**：

| 写法 | 意思 |
|---|---|
| **`-P`**（大写） | **Port** —— 别把 8000 翻译成 `irdmi` |
| **`-p`**（小写） | **process** —— 后面要跟 PID |

**Linux 上用 `ss`**（macOS 没有）：

```bash
ss -tlnp                 # 所有 TCP 监听 + 进程
ss -tlnp | grep 8000
```

| 参数 | 意思 |
|---|---|
| `-t` | TCP |
| `-l` | 只看 LISTEN |
| `-n` | 不解析名字 |
| `-p` | 显示进程 |

### 停进程

```bash
kill PID              # 优雅停止（SIGTERM，能收尾）
kill -9 PID           # 强杀（SIGKILL，来不及收尾）⚠️ 最后手段
kill $(lsof -ti :8000)    # 按端口杀（最常用）
pkill -f 进程名        # 按名字杀
```

### 测接口 `curl`

```bash
curl -s -o /dev/null -w "%{http_code}\n" URL          # ⭐ 只看状态码
curl -s -o /dev/null -w "%{time_total}s\n" URL        # 只看耗时
curl -s URL | head -c 40                              # 响应体前 40 字节
curl -s -X POST -H "Content-Type: application/json" \
     -d '{"k":"v"}' URL                               # POST JSON
curl -s -H "Authorization: Bearer xxx" URL            # 带认证头
curl -v URL                                           # ⭐ 看完整握手（调试）
curl --max-time 2 URL                                 # 超时 2 秒
```

**三种状态码**：

| 码 | 意思 |
|---|---|
| **`200`** | 门通了，正常 |
| **`404` / `500`** | **门通了**，业务逻辑问题 |
| **`000`** | **连不上**（curl 自己的标记，不是 HTTP 码） |

### 看日志

```bash
tail -f app.log                              # 实时跟（Ctrl+C 退出）
tail -f app.log | grep --line-buffered ERROR # 实时只看错误
tail -100 app.log                            # 最后 100 行
tail -30 app.log | grep -i error             # ⭐ 最后 30 行里的错误
grep -c ERROR app.log                        # 数几条
```

**`tail | grep` vs `grep | tail`**：

| 写法 | 意思 |
|---|---|
| **`tail -30 \| grep`** | 只看最后 30 行，在里面找 → **看"最近的记录"** |
| `grep \| tail -20` | 全文找，取最后 20 条 → **看"最近 N 条错误"** |

## 四、踩的坑

| # | 现象 | 原因 | 正确做法 |
|---|---|---|---|
| 1 | `lsof: unacceptable port specification in: -i :` | **冒号后面没写端口号** | `lsof -i :8000` |
| 2 | `lsof: illegal process ID: -n` | **大小写错了**：`-p` 是进程 | `-P -n`（大写 P） |
| 3 | `lsof -i :8000` 没输出 | 服务没起 / 已死 | **先 `pgrep -fl`** |
| 4 | `command not found: pthon3` + `exit 127` | **命令拼写错** | `which python3` 验证 |
| 5 | `[1] + exit 127` | **后台任务立刻死了** | 看退出码，别急着查端口 |
| 6 | `Serving HTTP` 还没出现就查端口 | 端口还没绑上 | **先 `sleep 1`** |
| 7 | 日志文件是空的 | **忘了 `2>&1`** | `> app.log 2>&1` |
| 8 | 本机能访问、别人不能 | 绑了 `127.0.0.1` | 绑 `0.0.0.0` |
| 9 | 端口显示成 `irdmi` | `lsof` 把 8000 翻成了服务名 | 加 `-P` |
| 10 | `&` 起的服务过一会儿就没了 | **关终端它就死** | 用 `nohup`（Day 34） |

### `2>&1` 是什么（**第一大坑**）

```bash
nohup 命令 > app.log 2>&1 &
#           └────┬────┘ └─┬─┘
#             stdout     stderr 也指过去
```

| 编号 | 名字 | 是什么 |
|---|---|---|
| `1` | stdout | 正常输出 |
| `2` | stderr | **报错** |

**`> app.log` 只接了 `1`。报错走 `2`，你看不到。**

**实测对比**：

```
$ nohup python3 bad.py > bad2.log &      → cat bad2.log = 空
$ nohup python3 bad.py > bad3.log 2>&1 & → cat bad3.log = SyntaxError: ...
```

### 退出码（写脚本会用到）

```bash
命令
echo $?          # 0=成功，127=命令没找到，130=Ctrl+C，2=用法错
```

## 五、macOS 和 Linux 的差异

| 事情 | macOS（BSD） | Linux（GNU） |
|---|---|---|
| **看端口监听** | `lsof -i :8000 -P -n` / `netstat -an \| grep LISTEN` | **`ss -tlnp`** |
| `ss` | ❌ 没有 | ✅ |
| `netstat` | ✅（BSD 版） | 可能没装（`net-tools`） |
| `sed -i` | 必须 `sed -i '' ...` | `sed -i ...` |
| `grep -P` | ❌ | ✅ |

**`ss` vs `netstat`**（面试常问）：
`ss` **更快**（直接读内核），是新标准；`netstat` 属于 `net-tools`，很多新系统已经不预装了。
